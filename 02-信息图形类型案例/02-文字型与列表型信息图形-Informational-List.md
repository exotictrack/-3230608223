# 02 文字型 / 列表型信息图形（Informational / List Infographics）

## 1. 定义与核心边界

以**文本信息的结构化呈现和快速检索**为主，而不是以连续量化图形为核心。典型组织包括清单、分类解释、步骤说明、知识点集合、FAQ、A–Z 图鉴与带短注释的目录。文字型（Informational）更关注概念阐释；列表型（List）更关注多个信息项的并列呈现，两者经常重叠但不完全相同。

**重要区分**：列表序号可能表示“顺序编号”“操作步骤”“重要程度排名”三种不同逻辑；版面使用 01/02/03 并不能自动推断有时间先后。若条目存在父子关系，可能具有层级逻辑；若按属性归类，可能具有编目逻辑。

## 2. 数据 / 内容逻辑

- **最小信息单元**：`条目ID | 标题 | 正文 | 类别 | 顺序规则 | 关键词 | 说明/示例 | 来源`。
- **列表排序**：主张强弱、任务流程、检索字母序、重要性排序和随机并列必须在标题/图例中显式区分。
- **信息颗粒度**：同一层的条目应使用近似的语义粒度与句式，避免一项是“行业”、另一项是“某个产品”的层级错位。
- **证据来源**：名词解释、数字事实、实践建议应分别标注；作品上没有出现的结论不能从排版风格中推断。

## 3. 可选的统计方式

文字/列表信息图形**不要求存在统计图**。当条目包含频数、百分比或排序分数时，可引入数字徽记、微型条、点标记、小多图、比例卡等；必须检查：数值单位是否统一、排名依据是否明确、百分比的分母是否一致。若没有数据，却用 70% 形状装饰，应记录为伪定量暗示，而非统计分析。

## 4. 视觉编码与版面设计

| 编码 | 功能 | 核查点 |
| --- | --- | --- |
| 字号/字重 | 标题—副标题—条目—注释的阅读优先级 | 是否层级清楚、正文可读 |
| 点/编号 | 项目定位，步骤或索引符号 | 编号是否被错误理解为排名 |
| 线/分割 | 区分组别，组织扫描路线 | 分割线是否过密并掩盖分组逻辑 |
| 面/卡片 | 聚合相似内容，形成模块 | 卡片大小差异是否暗示不当重要程度 |
| 图标/插画 | 强化主题语义与记忆点 | 图标能否不依赖猜测识别 |
| 色彩 | 组别编码、信息强调、警示 | 对应关系能否跨整张图保持一致 |
| 留白/对齐 | 降低视觉噪声，支持扫读 | 不同模块之间的间距是否反映层级 |

可按读图习惯选择 Z 型、F 型或垂直纵列阅读，但这是**设计选项**，不能在未观察眼动数据时断言所有读者会按此路径浏览。

## 5. 信息架构与视觉叙事

**信息架构**：范围与读者 → 主概念 → 分组维度 → 条目标题与说明 → 可选比较/例外 → 结语和出处。

**视觉叙事**可以是“问题 → 要点清单 → 应用建议”，也可以是“分类地图 → 分组探索 → 自主查找”。若为操作清单，应明确前后依赖；若为常识图鉴，提供自由跳读；若为排名榜单，应公布评分标准，不能把主观好恶当事实。

## 6. 案例分析时必须记录

- 原图的分组数量、条目数、标题层级、编号含义、文字与图标的配对关系。
- 是否存在重复句式/统一视觉模版，文本过密时如何处理信息密度。
- 哪些元素是文字表达，哪些通过形状或符号增强了理解。
- 数值是核心信息、辅助举例还是纯装饰？
- 作品是否有明确阅读序列、层级关系或字母索引功能？

## 9. 制作步骤（待验证）

先确定内容边界与条目标准；检查排序规则；压缩每条句子为“短标题 + 一句说明 + 必要的数字/例子”；建立视觉层级和网格；最后添加真正有语义作用的图标并进行可读性核查。新增案例后对“每屏条目数、字图比例、模块布局”的假设作修订。
