# SC-IMG 风格分析与风格克隆系统

SC-IMG 从参考图中提炼可复用的视觉关系，支持换题材、扩展场景、迁移与修订。从同一生成规范导出中文 JSON、英文 JSON、中文简易提示词和详细自然语言提示词。

运行正文在 [SYSTEM.md](SYSTEM.md)，系统版本与入口见 [manifest.json](manifest.json)。这套系统可直接由能读文本的模型执行。读取图像、访问远程文件、持久记忆和出图以实际环境的能力为准。

## 三种启动方式

### 上传

把 **SC-IMG 启动文档.txt** 上传到网页版模型。也可以使用本仓库的 SYSTEM.md。有实际参考图时一并附上。需要复用时，可以附上已保存的风格档案 JSON 和新主题。

> 启动风格分析和克隆系统。先分析附件图片，建立带证据的风格档案。请同时导出四版可换主题的提示模板。

> 启动 SC-IMG。用附件中的风格档案，主题换成〔新主题〕，用途是〔用途〕，保留风格核心。输出四版提示词。

### GitHub 读取

将本仓库包内的内容放在目标仓库根目录。给能访问该仓库的模型指定 SYSTEM.md。固定版本复用时可直接指定文件的提交对应链接。档案路径可以与系统在同一仓库，也可以单独提供。

> 启动 SC-IMG。读取我给出的 GitHub 文件链接中的 SYSTEM.md。报告读到的规范版本。读取我指定的风格档案和版本，然后将主题改成〔新主题〕，输出四版提示词。

如果模型只能看见 README 或无法访问私有仓库，将 SYSTEM.md 和档案文件上传即可继续。

### 记忆调用

复制 [MEMORY.md](MEMORY.md) 的调用卡，填入实际系统入口。完成第一份风格档案后，记下档案 ID、版本与可读位置。若平台可保留持久知识文件，可以将系统正文与风格档案一并存放。

> 请记住我的 SC-IMG 调用卡。以后我说「启动 SC-IMG」或「调用某个风格」时，尝试读取我指定的系统入口与风格档案。

> 启动 SC-IMG，调用 SP-001@1.0.0，主题改为〔新主题〕，导出四版提示词。

调用卡可携带核心摘要。精确复用时检查模型是否已读取对应版本的完整档案。用户可把完整文件放在同一项目知识、已连接工作区或可访问的仓库里。

## 启动回执示例

| 输入 | 预期回执 |
|---|---|
| 只上传完整运行文档并说启动 | 系统 1.0.0 已读。当前风格档案尚未提供。可上传参考图，或提供档案与新主题。 |
| 指定版本的仓库文件与档案均可读 | 报告实际系统版本、读取位置和档案 ID@版本。有明确任务时接着处理。 |
| 新对话里只有记忆卡 | 报告仅见调用卡。尝试访问卡上的位置，说明哪些材料已取得。 |

## 仓库内容

| 文件 | 用途 |
|---|---|
| [SYSTEM.md](SYSTEM.md) | 完整运行协议。上传、仓库和记忆入口共用。 |
| [MEMORY.md](MEMORY.md) | 触发语、来源位置和风格登记模板。 |
| [templates](templates/) | 风格档案、项目任务、生成规范、验收与分镜 JSON。 |

| [examples](examples/) | 一份教学风格经可填槽模板、同题变体、主题扩展和跨题材迁移的案例。另有准确中文文案的双语导出用例。 |
| [tools](tools/) | 从已填写的生成规范导出四版，附核心覆盖和规格检查。 |
| [DESIGN.md](DESIGN.md) | 字段取舍、与附件方法的对应、验收边界。 |

## 可选的本地导出

使用装有 Node.js 18 或更高版本的环境，在仓库根目录运行。工具使用 Node.js 内置模块。

    node tools/export-prompts.cjs examples/greenhouse.render.json examples/style-profile.json examples/greenhouse.task.json
    node tools/verify.cjs

第一条命令把四版提示词写到标准输出。档案与任务参数可省略。提供档案时会核对 ID、版本、核心规则覆盖、依赖和冲突。提供任务时再核对必须锁定、输出规格和准确文案。双语描述由使用者或模型填进统一规范。程序校验结构、槽位、规则引用和共同规格，中文与英文的关系和语义由逐项审查确认。
